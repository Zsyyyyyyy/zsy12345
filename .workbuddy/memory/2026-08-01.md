## notes.html 笔记刷新机制
- 笔记数据由 `build-notes.js` 把 `notes/` 下所有 `.md` 静态打包进 `notes-data.js`，页面只读该静态文件，不实时读 `.md`。
- 用户改 md 后网站没变，原因即未重跑构建；已重跑 `node build-notes.js` 刷新 `notes-data.js`（现 4 篇笔记，git 显示已 M）。
- 约定：每次改/增 `.md` 后须 `node build-notes.js` 并刷新浏览器（必要时强制刷新清缓存），提交时把 `notes-data.js` 一并提交。

## notes.html 新增复制功能
- 阅读视图（readView）标题右侧加「复制源码」「复制文本」两个按钮：复制源码=md 原文；复制文本=渲染后纯文本。
- 复制逻辑：优先 `navigator.clipboard`，`file://` 非安全上下文回退 `execCommand('copy')`；底部 toast 反馈。
- 样式：`.post-head-right` / `.copy-btn` / `.toast`（含 `.ok` 变体）；窄屏 `.post-head` 换行、按钮下移。

## 改 md 后「提交了还是不行」根因与修复
- 根因：仓库连了 GitHub 远程（origin = github.com/Zsyyyyyyy/zsy12345），站点从仓库部署（GitHub Pages 类）。`git commit` 只存本地历史，**不会**更新线上；必须 `git push`。用户提交后网站无变化即因未 push。
- 修复：在 `build-notes.js` 末尾加一步——构建时给 `notes.html` 里 `notes-data.js` 引用打版本号 `?v=<时间戳>`，防浏览器/静态托管缓存旧数据。已重跑构建并 `git push origin main`（`28cd075..eb6b42c`）。
- 关键认知：本项目站点 = GitHub Pages 部署；本地改完 → `node build-notes.js` → `git add` → `git commit` → `git push` 才算真正上线。
